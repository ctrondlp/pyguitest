# examples/images

Scratch space for template matching. Nothing here is committed except this
file and `.gitignore`.

## The demo pair

    python3 examples/08_find_by_image.py --demo

writes two PNGs here and searches one for the other:

| file | what it is |
|---|---|
| `haystack.png` | 240x160, every pixel a different colour |
| `button.png` | 24x16, cut from the haystack at (96, 60) |

It needs no screenshot, no desktop and no window -- only ImageMagick's
`compare` -- so it is the fastest way to confirm template matching works on
this machine before trying it against a real screen. The colours are
position-unique on purpose: a flat image would match anywhere, and a demo
that passes for that reason teaches nothing.

Both files are generated by `pyguitest.png` rather than committed, which
keeps binary files out of the repository and exercises the PNG encoder in
the same run.

## Your own templates

Put crops of your own screen here too -- `.gitignore` covers them.

    python3 examples/08_find_by_image.py images/my-button.png
    python3 examples/09_gui_spy.py --find images/my-button.png

A real template has to come from **your** screen: it carries the theme,
font rendering, scaling and colour profile of wherever it was cropped, so
one made on another machine usually will not match. Take a screenshot with
example 05, then crop the control out of it tightly. That is the whole
reason the demo pair above is synthetic rather than a picture of a button
-- a committed screenshot could not match anyone's desktop, including the
one it came from at a different scaling.
